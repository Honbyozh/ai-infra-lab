## 项目周期

- 启动日：2026-07-27（周一）
- 正式学习开始：当天先完成启动门禁，通过后继续执行 W01-D1

## 开始学习

1. 按 [启动前准备工作](docs/startup-preparation.md) 完成当前机器的启动门禁，并在 `docs/prestart/` 单独记录准备耗时和证据。该文档是唯一有效的启动准备清单；历史环境记录已清除。
2. 如果门禁在计划启动日当天通过，可以当天继续 W01-D1；若当天无法通过，则 W01-D1 顺延到门禁通过后的首个可执行日，并整体调整后续日期。
3. 在 [32 周逐日学习计划](AI-Infra-32-Week-Daily-Learning-Plan.md) 中确定当天任务和验收条件，从 [每日学习记录模板](docs/templates/daily-log.md) 新建正式学习记录。
4. 在规定时长内学习和实验，将代码、命令输出、截图或测试结果保存到仓库。
5. 按 [执行与验收规则](docs/execution-guide.md) 完成自测；当天专属验收与四项统一验收全部通过后才可标记完成。
6. 更新 [项目进度表](docs/progress.md)，并在当天记录中写明实际用时、证据、未决问题和下一步。

日志文件统一使用：

```text
docs/logs/YYYY-MM-DD-wNN-dN.md
```

记录分工：

- `docs/prestart/`：启动准备的实际过程、耗时和证据。
- `docs/logs/`：32 周正式学习的每日记录。
- `docs/reviews/`：每周复盘与周状态。
- `docs/progress.md`：只做日期、状态和记录链接的汇总索引。

硬件或环境暂不具备时，不直接视为完成；允许替代验收的项目登记到 [延后补验台账](docs/deferred-validations.md)。启动准备不计入 32 周正式学习时长。

## 完成定义

每日任务必须同时满足：

- 能复现：从新终端按记录可得到相同结果。
- 有证据：保留代码、测试输出、指标、截图或笔记。
- 能解释：可以不看资料回答当天关键问题。
- 有边界：写出至少一个限制、失败场景或未决问题。

只完成阅读或达到计划时长，不等于通过验收。
